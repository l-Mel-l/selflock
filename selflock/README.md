# SelfLock — «Самоконтроль»

> Больше контроля. Больше времени на главное.

SelfLock — приложение для Windows. Пользователь заранее, в спокойном состоянии, задаёт правило для приложения или сайта, а SelfLock его соблюдает: предупреждает, когда лимит достигнут, один раз разрешает отложить закрытие и потом закрывает ресурс. Нужно оно, чтобы учёбу и работу не съедали соцсети, игры, YouTube Shorts и TikTok.

Работает локально, без интернета. Правила, счётчики и статистика хранятся в `%APPDATA%\SelfLock`.

## Как запустить

Нужен Windows 10/11.

- **Готовый exe:** `dist\SelfLock.exe` — один файл, .NET ставить не надо.
- **Из исходников:** нужен [.NET SDK 10](https://dotnet.microsoft.com/download):
  ```bash
  dotnet run --project src/SelfLock.App
  ```
- **Собрать exe самому:** `publish.bat`. Результат появится в `dist\`.
- **Тесты:** `dotnet test`

При первом запуске SelfLock объясняет, какой доступ ему нужен и зачем. Пока пользователь не нажмёт «Разрешить», правила не включаются (пункт 6 MVP).

## Как устроено правило

Правило состоит из трёх частей, как в отчёте:

| Часть | Варианты |
|---|---|
| **Ресурс** | приложение (процесс: `steam`, `telegram`…) или сайт (`youtube.com`; можно указать раздел, например `youtube.com/shorts` — тогда обычные видео правило не затронет) |
| **Условие** | N минут **непрерывно** (перерыв короче заданного в настройках не сбрасывает сеанс) · N минут **за день** · **запрещённое время суток** (окно может проходить через полночь, например 22:00–07:00) |
| **Режим** | **мягкий:** предупреждение с отсчётом; отложить можно **один раз** и только на время, заданное в правиле (по желанию — выбрать меньшее значение в момент предупреждения); потом ресурс закрывается · **жёсткий:** закрывается сразу, без отсрочки |

После срабатывания ресурс блокируется: для «непрерывно» — на заданное число минут, для «за день» — до полуночи, для окна по времени — до его конца. Если в это время открыть ресурс снова, SelfLock снова его закроет. Блокировка переживает перезапуск SelfLock и перезагрузку ПК.

**Защита от себя.** Выключить или удалить правило, ослабить его, поставить SelfLock на паузу или выйти из него можно только после обязательной паузы (по умолчанию 30 сек). Пока ресурс заблокирован, его правило нельзя ни изменить, ни удалить.

## Что из отчёта реализовано

**MVP (обязательно)**
- [x] 1. Создание правила: ресурс, условие, режим реакции
- [x] 2. Учёт времени в приложении или на сайте (считается только время, когда ресурс в активном окне)
- [x] 3. Мягкий режим: предупреждение и однократная отсрочка на время из правила
- [x] 4. Закрытие ресурса после отсрочки
- [x] 5. Жёсткий режим: закрытие сразу
- [x] 6. Объяснение и проверка нужных разрешений; без них правила не включаются

**Желательно**
- [x] Дополнительные условия: время за день, запрещённое время суток *(лимита на число запусков за день пока нет)*
- [x] Блокировка повторного открытия до конца периода
- [x] Защита правил: задержка подтверждения и запрет изменений во время блокировки
- [x] Статистика: время по дням, топ приложений и сайтов, журнал срабатываний
- [x] Ограничение раздела сайта (`youtube.com/shorts`, `vk.com/clips`)

**Риски из отчёта и что с ними сделано**
- *Сон и гибернация:* время считается по системным часам. Если между тиками прошло больше 5 секунд (ПК спал, часы перевели), этот промежуток не засчитывается.
- *Фоновый процесс закрыли случайно:* при закрытии окна SelfLock сворачивается в трей, а не выходит. Автозапуск с Windows включается в настройках. Выход из SelfLock защищён задержкой.
- *Определение сайтов в браузере:* адрес читается из адресной строки через UI Automation (Chrome, Edge, Яндекс Браузер, Opera, Brave, Vivaldi, Firefox). Если адрес прочитать не удалось, сайт определяется по заголовку окна; для разделов вроде Shorts такая подстановка не используется.

## Ограничения (честно)

- SelfLock не защищён от принудительного завершения через диспетчер задач. Внутри своих прав пользователь может закрыть что угодно; защита от этого возможна только через службу Windows и права администратора, это следующая версия.
- Приложения, запущенные от администратора, SelfLock закрыть не может: у него нет таких прав. Окно такого приложения он пытается свернуть.
- Время на сайте считается, только пока окно браузера активно. Видео в фоновом окне не засчитывается.
- Вкладку заблокированного сайта SelfLock закрывает сочетанием Ctrl+W, и только если эта вкладка сейчас активна.

## Структура

```
src/SelfLock.Core      логика без WinAPI: модели, движок правил, сопоставление ресурсов, хранилище
src/SelfLock.App       WPF-приложение: окна, трей, учёт активного окна (WinAPI), чтение адреса (UI Automation), закрытие
tests/SelfLock.Tests   модульные тесты движка и сопоставления (xUnit)
docs/ТЕСТ-КЕЙСЫ.md     чек-лист и тест-кейсы основного сценария
tools/make_icon.py     генерация иконки
```

Каждую секунду `AppHost` берёт снимок активного окна, который фоновый `ForegroundSampler` обновляет примерно три раза в секунду, и передаёт его в `RuleEngine.Tick`. Движок возвращает события: напоминание, предупреждение, закрытие, разблокировку. `AppHost` по ним показывает окна, а `Enforcer` закрывает ресурс.

## Режим для тестирования (QA)

Переменные окружения, в обычной работе не задаются:

| Переменная | Что делает |
|---|---|
| `SELFLOCK_DATA` | папка с данными вместо `%APPDATA%\SelfLock`, чтобы не трогать настоящие правила |
| `SELFLOCK_FAKE_FG` | подменяет активное окно: `charmap` или `chrome\|https://youtube.com/shorts/abc` |
| `SELFLOCK_OFFSCREEN` | `1` — предупреждения, экран блокировки и главное окно открываются за пределами экрана и не забирают фокус |

Подробные сценарии — в [docs/ТЕСТ-КЕЙСЫ.md](docs/ТЕСТ-КЕЙСЫ.md).
